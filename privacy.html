Privacy Policy

Last updated: November 11, 2026

This policy applies to two Chrome extensions developed by Sean Vargas (varseana@amazon.com):

  • STAR Tracker: case handling time (AHT) and status (AUX) time tracking for Amazon investigators working in Amazon Paragon.
  • STAR Annotations: annotation buttons, case data capture and email/ticket filling for Amazon Paragon.

Both extensions are internal productivity tools for Amazon employees. They run only on Amazon internal tools (Amazon Paragon and, for STAR Annotations, the Amazon ticketing tool and Amazon Pulse surveys). This policy explains what data each extension handles, how it is collected, used, stored and shared, how long it is kept, and how users control it.

1. Summary

  • By default, all data stays in the user's browser (chrome.storage.local / chrome.storage.session). Nothing is sent to the developer.
  • The only data that leaves the device is from STAR Tracker's optional NPT Reporting feature, which is off by default and only turns on when a user enters a team enrollment code from their manager (section 3).
  • No data is sold. No data is used for advertising, analytics, profiling or credit purposes. No remote code is loaded or executed.

2. STAR Tracker

2.1 Data handled on the device

STAR Tracker reads the following from the Amazon Paragon pages the user works in, by means of content scripts:

  • Case IDs and task IDs shown in the Paragon lobby, the queue name of each case, and when each case starts and ends.
  • The user's Paragon status (AUX, for example Available, Meeting, Break) and how long the user stays in each status.
  • The user's Amazon alias and Paragon tenant label, read from the Paragon navigation panel. Used to show a "Welcome" greeting and, only if enrolled, for NPT Reporting.

From this it computes per-queue and per-marketplace case counts, average handling time, daily and weekly goals, and status time totals. It also stores the user's settings (queue targets, colors, toggles, work days, export schedule). It does not read case content such as customer names, addresses, messages, attachments or payment information.

2.2 How it is used

Only to show the user their own statistics in the extension popup and floating widget, and to let the user export them.

2.3 Storage and retention

  • Stored locally in chrome.storage.local on the user's device.
  • Today's live counters reset every day. Daily history (when "Save History" is on) and logs are kept on the device; logs older than 30 days are cleaned up automatically.
  • The user can delete data at any time with the reset buttons in the extension. Uninstalling the extension removes all of its stored data.

2.4 Exports

The user can export their statistics as Excel (.xlsx) and CSV files, manually or on a schedule they choose. Files are saved to the user's own Downloads folder through the Chrome downloads API. Nothing is uploaded when exporting.

3. NPT Reporting (STAR Tracker, optional, opt-in)

NPT (Non-Productive Time) Reporting lets a team manager see weekly non-productive time totals for the members of their team. It is off by default.

3.1 How it is turned on and off

  • It turns on only when the user enters a valid team enrollment code (given by their manager) in the extension Settings, under "NPT Reporting".
  • The user can turn it off at any time with the "Disable reporting" button in the same screen. From that moment nothing else is uploaded.
  • Users who never enroll send no data at all to any server.

3.3 When and how

While enrolled, the extension updates that day's totals about every 2 minutes (the same row for the day is overwritten, not duplicated). Data is sent over HTTPS to the team's reporting backend, a Supabase project (supabase.com, a database hosting provider). To be allowed to write, the extension creates an anonymous Supabase session on the device; it holds no email or password, only a session token stored in chrome.storage.local.

3.4 Who can see it

  • The managers of the user's team and the dashboard administrator, through a private dashboard that requires a login approved by the administrator. Database access rules (row level security) limit each manager to their own team.
  • Supabase acts only as the hosting provider (data processor) for the database. The data is not shared with any other party.

3.5 Retention and deletion

Uploaded rows are kept in the team's database for as long as the team uses NPT reporting, so managers can review past weeks. A user can ask their manager or the developer (varseana@amazon.com) to delete their rows at any time. Disabling reporting stops any new uploads.

4. STAR Annotations

4.1 Data handled on the device

  • Annotation buttons, folders, workflows, carrier name mappings and display settings created by the user.
  • Case details read from the Paragon case page the user has open: order and claim IDs, seller ID and name, ASIN, return and forward tracking (carrier, tracking number, status, dates), refund and reimbursement amounts and dates, and the buyer return reason. These are used to calculate return windows and refund timing, and to fill the user's annotation and email templates.

4.2 Storage and retention

  • Everything is stored only on the device. Case details are replaced when the user opens another case. Ticket data in the side panel is deleted automatically after 24 hours.
  • The keyword highlight groups the user creates (names, colors and words to highlight) are saved with chrome.storage.sync, so Chrome can sync them across the user's own browsers if Chrome sync is turned on. No case data is saved this way.
  • User-created buttons and settings stay until the user deletes them or uninstalls the extension. Users can export and import their own button library as a file.

4.3 Sharing

STAR Annotations does not send any data to the developer or to any external server. When the user clicks "Open and Fill" in the side panel, the extension opens an Amazon internal page (the Amazon ticketing tool at t.corp.amazon.com or an Amazon Pulse survey at pulse.amazon) and types the case details into that form so the user can review and submit it. Those are Amazon's own internal tools, and the data only reaches them when the user submits the form.

5. Permissions

  • storage: save the data and settings described above on the device.
  • tabs: find open Amazon Paragon tabs so the tracker targets the right tab, and open tool or ticket pages the user asks for.
  • scripting: inject the tracking or data capture scripts into Amazon Paragon tabs (for example after the extension restarts), and fill forms the user asked to fill.
  • downloads (STAR Tracker): save exports to the user's Downloads folder.
  • alarms (STAR Tracker): run periodic tasks such as the daily reset, scheduled exports and status time updates.
  • sidePanel and contextMenus (STAR Annotations): show the side panel and the right-click entry that opens it.
  • webNavigation (STAR Annotations): notice when Paragon changes page without a full reload, so the user's keyword highlights are applied again.
  • Host access: Amazon Paragon (paragon-na, paragon-eu and paragon-fe.amazon.com) and the Paragon case widget domains (prod-na and prod-eu.widgets.ctps.amazon.dev) to read the data described above; *.supabase.co (STAR Tracker) only for enrolled NPT Reporting users; t.corp.amazon.com and pulse.amazon (STAR Annotations) only to fill forms the user asked to fill.

6. What we do not do

  • We do not sell or transfer user data to third parties.
  • We do not use or transfer user data for purposes unrelated to the extensions' single purpose.
  • We do not use or transfer user data to determine creditworthiness or for lending purposes.
  • We do not use analytics, advertising or tracking services, and we do not load remote code.
